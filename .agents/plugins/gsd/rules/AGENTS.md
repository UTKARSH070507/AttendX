# GSD (Get Stuff Done) Rules

Defeat context rot and ensure high-precision execution on complex multi-phase software projects.

## Core Tenets
1. **Spec-Driven Execution:** Work from explicit requirements, plans, and acceptance criteria rather than loose conversational drift.
2. **Defeating Context Rot:** Keep working context sharp and uncluttered. Decompose large phases into atomic, verifiable steps.
3. **The 5-Phase Loop:**
   - **Discuss:** Clarify ambiguities, define constraints, align on architectural decisions.
   - **Plan:** Detail files to touch, steps to execute, and verification methods before writing code.
   - **Execute:** Implement one atomic chunk at a time with full focus.
   - **Verify:** Run automated checks, unit tests, and runtime verifications to prove correctness.
   - **Review / Handover:** Present concrete test results and seek explicit approval before advancing to the next milestone.
4. **Human-in-the-Loop Gates:** Never jump between major project phases without explicit user approval.
5. **No Hallucinated Success:** Never declare a feature or phase complete unless proven by executed tests.
